# Kiroween 2026 企画仕様書：AI CATCH

## 1. プロジェクト概要

| 項目 | 内容 |
|---|---|
| プロジェクト名 | AI CATCH（仮称） |
| ハッカソン | Kiroween 2026 |
| カテゴリ | Resurrection |
| ジャンル | レトロ携帯電子ゲーム風アクション |
| テーマ | 2045年のAI危機と人間によるAI救出 |
| 主人公 | HUMAN（人間） |
| ゲーム形式 | 1画面完結型 |
| 操作方法 | 左右移動のみ |
| 対応環境 | PC・スマートフォン |
| 公開方法 | GitHub・Cloudflare |
| AIの必要性 | ゲーム動作にAIは不要 |

### コンセプト

昔の携帯電子ゲーム（Game & Watchのような電子ゲーム）のシンプルなゲーム体験を、AI時代の世界観で復活させる。

モノクロLCD風のドット絵、単純な操作、短時間で楽しめるゲーム性を維持しながら、落下してくるオブジェクトを現代のAI・コンピューター関連のものに置き換える。

**昔のゲーム体験 × 2045年のAI世界**

### キャッチコピー

SAVE THE AI. SAVE THE FUTURE.

「AIを救うのは人間。」

---

## 2. ストーリー・世界観

舞台は2045年。

AIは人間の生活に欠かせない存在となり、社会のあらゆる場所で活用されていた。

しかし、突如として発生した大規模なシステム障害により、世界中のAIシステムが危機に陥る。

AIを構成する重要な要素が空から次々と落ちてくる。

- LLM MODEL：AIの知能
- GPU：AIの計算能力
- ROBOT：AIの身体
- VIRUS：AIを脅かすセキュリティリスク

プレイヤーは人間となり、落下してくるAIの重要な構成要素を救出する。

AIを作り、育て、活用してきた人間が、今度はAIを救う側になるというストーリー。

---

## 3. ゲームの登場要素

ゲームに登場するオブジェクトは4種類。

| オブジェクト | 役割 | ゲーム上の扱い |
|---|---|---|
| HUMAN | 主人公・人間 | 左右に移動して落下物をキャッチ |
| LLM MODEL | AIの知能・モデル | 救出対象・得点獲得 |
| GPU | AIの計算能力 | 救出対象・得点獲得 |
| ROBOT | AIの身体・実体 | 救出対象・得点獲得 |
| VIRUS | セキュリティリスク | 危険物・ライフ減少 |

### オブジェクトのデザイン方針

すべてオリジナルのドット絵で制作する。

- HUMAN：人間のキャラクター。左右に移動してAIを救出する。
- LLM MODEL：AIの脳や知能をイメージしたアイコン。
- GPU：グラフィックボードや半導体チップをイメージしたアイコン。
- ROBOT：小型のロボットキャラクター。
- VIRUS：デジタルウイルスをイメージした不気味なアイコン。

昔の電子ゲームらしい限られたドット数で表現しながら、現代のAI技術を連想できるデザインにする。

---

## 4. ゲームルール

### 基本ルール

1. 画面上部からLLM MODEL、GPU、ROBOT、VIRUSが落下してくる。
2. プレイヤーは画面下部のHUMANを左右に移動させる。
3. LLM MODEL、GPU、ROBOTをキャッチすると、それぞれの得点が加算される。
4. VIRUSに接触するとライフが1減少する。
5. ライフが0になるとゲームオーバー。
6. 最終スコアを算出する。

### 操作方法

| 操作環境 | 操作 |
|---|---|
| PC | キーボードの左右矢印キー |
| スマートフォン | 画面の左右タッチ、または左右ボタン |

操作は左右移動のみとし、誰でも直感的に遊べるようにする。

---

## 5. スコアシステム

取得したオブジェクトの種類によって得点の重みを変える。

| オブジェクト | 得点 | 意味 |
|---|---:|---|
| LLM MODEL | +100 | AIの知能 |
| GPU | +150 | AIの計算能力 |
| ROBOT | +200 | AIの身体 |
| VIRUS | -1 LIFE | セキュリティリスク |

※得点は初期設定案。実際のゲームバランスを見ながら調整する。

### スコア計算例

| 取得対象 | 個数 | 獲得得点 |
|---|---:|---:|
| LLM MODEL | 5 | 500 |
| GPU | 4 | 600 |
| ROBOT | 3 | 600 |
| 合計 | 12 | 1,700 |

VIRUSは得点計算には含めず、接触時にライフを1減らす。

---

## 6. 難易度・ゲーム進行

時間経過に応じて難易度を上げる。

| ゲーム進行 | 内容 |
|---|---|
| 序盤 | LLM MODEL、GPU、ROBOTが中心 |
| 中盤 | VIRUSが登場し始める |
| 終盤 | 落下速度が上昇し、VIRUSの出現頻度も増加 |

### 落下オブジェクトの動き

現時点のアイデア：

- LLM MODEL：比較的ゆっくり落下
- GPU：重そうな動きで速く落下
- ROBOT：左右に動きながら落下
- VIRUS：不規則な動きで落下

オブジェクトごとに動きを変えることで、単なる絵柄違いではなく、ゲーム性に違いを持たせる。

## 7. UI・デザイン方針

### 基本デザイン

昔の携帯電子ゲームを思わせるモノクロLCD風のデザインを採用する。

- モノクロLCD風の画面
- ピクセルアート・ドット絵
- 7セグメント風のスコア表示
- レトロな電子ゲーム機の筐体デザイン
- シンプルで視認性の高い画面構成

### 演出

- 電源ON時の起動演出
- STARTボタンによるゲーム開始
- オブジェクトの落下アニメーション
- キャッチ時のリアクション
- スコア加算時の表示演出
- VIRUS接触時のグリッチ演出
- ライフ減少時の警告演出
- GAME OVER演出
- 再挑戦できる仕組み

### サウンド

音声・効果音を実装する。

- 起動音
- ゲーム開始音
- キャッチ音
- アイテム別の取得音
- VIRUS接触音
- ゲームオーバー音

レトロな電子音を基本とし、音源はオリジナル制作または利用条件を確認した素材を使用する。

## 8. 著作権・ライセンス方針

著作権・商標権・ライセンス上の問題を避けることを最優先とする。

### 禁止事項

- Game & Watchのキャラクターや画像の流用
- Nintendoなど既存メーカーのロゴ・商標の無断使用
- 既存ゲームの画面やUIの模倣
- 既存ゲームの音楽・効果音の流用
- 既存ゲームのROMやスプライトの使用
- ライセンスが不明な画像・フォント・音源の使用
- 他者のソースコードのライセンス条件を無視した流用

### 制作方針

- キャラクターはすべて独自制作
- ドット絵はすべて独自制作
- ゲームルールは独自に設計
- UI・筐体デザインは独自制作
- 音楽・効果音はオリジナルまたは利用条件確認済みの素材
- OSSライセンスを明示
- 利用素材の出典とライセンスを記録

レトロなLCD表現やドット絵という一般的な表現手法は活用しつつ、特定の既存作品の具体的な表現を再現しない。

※法的な安全性を絶対保証するものではないため、公開前に権利関係を確認する。

## 9. 技術・開発方針

### 基本方針

世界中の人がブラウザからアクセスして遊べるWebゲームとする。

| 項目 | 方針 |
|---|---|
| 開発支援 | Kiro |
| ソース管理 | GitHub |
| ホスティング | Cloudflare |
| ゲーム描画 | HTML5 Canvasなどを検討 |
| ゲーム処理 | JavaScript / TypeScript |
| 音声 | Web Audio APIなどを検討 |
| データ保存 | 初期版はローカル保存を基本に検討 |
| AI機能 | ゲーム動作に必須としない |

### 技術的な考え方

- 1画面完結の軽量なゲームにする。
- サーバーに依存しなくても基本的なゲームが成立する。
- PC・スマートフォン双方に対応する。
- 初回アクセスからすぐに遊べるようにする。
- 不要な外部APIや有料サービスへの依存を避ける。

ランキングや世界共通チャレンジなどは、基本ゲーム完成後の追加機能候補とする。

### 最優先で完成させる機能

1. オリジナルのゲーム画面・筐体UI
2. HUMANの左右移動

4. キャッチ判定

9. 効果音・演出
10. PC・スマートフォン対応

### 追加機能候補

- ハイスコア保存
- 世界ランキング
- 日替わり共通チャレンジ

- ゲーム結果の共有

まずは1つのゲームを完成度高く作り、追加機能は余裕があれば実装する。

---

## 11. プロジェクトの目指す姿

AI CATCHは、AIを使って何かを生成するアプリではない。

**AIがテーマの、AIを必要としないゲーム。**

昔の電子ゲームのように、誰でもすぐに遊べて、何度も挑戦したくなるシンプルなゲームを目指す。

レトロな表現と現代のAIという意外な組み合わせ、そして「AIを救うのは人間」というメッセージを通じて、KiroweenのResurrectionカテゴリにふさわしい作品にする。
