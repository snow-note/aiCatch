## 3. 参加資格

### 参加可能

## 4. カテゴリ

参加者は Kiro（IDE / CLI / Web / Kiro Crew）を使用して動作するソフトウェアアプリを構築し、以下のいずれかのカテゴリに提出する必要がある。Kiroの使用が不十分な場合は審査員の判断で失格となる。

| カテゴリ | 内容 |
|---|---|
| **Resurrection** | お気に入りの廃止された技術を現代のイノベーションで復活させる。時代遅れの技術を今日の革新的手法で再構築する |
| **Frankenstein** | 異なる技術を縫い合わせて1つのアプリにする。一見互換性のない要素を組み合わせて予想外に強力なものを作る |
| **Skeleton Crew** | 明確で柔軟な骨組みとなるコードテンプレートを構築し、2つの異なるアプリでその汎用性を示す |
| **Costume Contest** | 任意のアプリを作るが、忘れられないような洗練されたホラー風UIを見せる。アプリの機能を高める不気味なデザイン要素を取り入れる |

## 5. プロジェクト要件

- **機能**: 動作可能なアプリであること。ビデオやテキスト説明の通りに機能すること
- **新規作成**: 提出期間開始後に新規作成されたプロジェクトであること。標準的な開発リソース（フレームワーク、ライブラリ、スターターテンプレート）の使用は可能だが、既存のコードや作業の取り込みは開示が必要
- **サードパーティ統合**: 第三者のSDK・API・データを使用する場合、その利用規約・ライセンス要件を遵守すること

## 6. 提出要件

以下をすべて提出する必要がある：

1. **動作するアプリケーションのURL**（ログインが必要な場合は認証情報を含める）
2. **テキスト説明**（プロジェクトの機能と特徴を説明）
3. **デモ動画**（3分以内、YouTubeで公開、プロジェクトが実際に動作する様子を含む）
4. **GitHubリポジトリの公開URL**（GitLab・BitBucketは不可）
   - すべてのソースコード・アセット・手順を含む
   - オープンソースライセンスファイルを含む（リポジトリトップに表示）
   - `/.kiro` ディレクトリをルートに含める（Kiroの使用実績を示す）。`.gitignore`に追加してはならない
5. **カテゴリとボーナスカテゴリの指定**
6. **Kiro使用方法の記述** — 審査員がKiroを効果的に使用した方法を理解できるように、以下を含める：
   - 使用したKiro製品（IDE / CLI / Web / Crew）とその違い
   - カスタムエージェントの作成・使用
   - エージェントフックによるワークフロー自動化
   - スペック駆動開発の活用
   - ステアリングドキュメントの活用
   - MCPによる機能拡張
   - プロパティベースドテスティング（PBT）の活用
   - Kiroパワーの活用

### 言語要件

提出物はすべて英語であること。英語以外の場合は、デモ動画・テキスト説明・テスト手順の英語翻訳を提供すること。

## 7. 審査基準

### ステージ1（合否判定）

プロジェクトがテーマに合致し、ハッカソンの指定ツールを合理的に使用しているかを合否で判定する。

### ステージ2（採点）

ステージ1を通過した提出物は、以下の等重み基準で評価される（各20%・10点満点）：

| 基準 | 配点 | 評価内容 |
|---|---|---|
| **Potential Impact**（潜在的影響） | 20% (10点) | 実際の問題を実際のユーザーに解決する説得力があるか。有用で直感的でアクセシブルか。実際に使われるものか |
| **Technological Implementation**（技術的実装） | 20% (10点) | Kiroをどれほど深く熟練して使用しているか。AI開発への戦略的アプローチはあるか。多様なKiroツールを効果的に使っているか。実験的取り組みはあるか |
| **Design**（デザイン） | 20% (10点) | 技術的なプロトタイプでなく、完全で一貫したプロダクト体験を提供しているか。直感的で洗練され意図的なデザインか |
| **Innovation/Idea**（革新性・アイデア） | 20% (10点) | コンセプトはどれほど創造的で斬新か。既存概念との違いは何か。独自の技術や公開リソースの組み合わせがあるか |
| **Presentation**（プレゼンテーション） | 20% (10点) | 動画はプロジェクトがエンドツーエンドで動作する様子を明確に示しているか。ピッチは何を解決し、誰のためで、なぜ重要かを伝えているか。創造的で記憶に残るか |

### 同点の場合

同点の場合、各基準を20点満点で再評価する。それでも同点の場合は+10点ずつ延長して勝者が決まるまで繰り返す。

## 10. AI CATCH にとっての重要ポイント

本プロジェクト（AI CATCH）がResurrectionカテゴリに提出する場合、以下が特に重要：

1. **Kiroの使用実績**: `/.kiro` ディレクトリを必ずルートに含める（`.gitignore`に追加しない）
2. **提出物は英語**: デモ動画・テキスト説明・テスト手順は英語で提出（日本語の場合は英語翻訳が必要）
3. **GitHub公開**: リポジトリは公開で、オープンソースライセンスファイルを含む
4. **3分以内のデモ動画**: YouTubeで公開
5. **Resurrectionカテゴリの要件**: 廃止された技術を現代のイノベーションで復活させる — レトロ電子ゲームをAI時代の世界観で復活させる本プロジェクトはこの要件に合致
